# Step 5: 实施

使用 `TaskCreate` 创建任务清单，按以下规则逐步实施。

## 5.1 测试

不强制要求全量测试：
- 对无副作用的工具函数编写单元测试
- 业务功能或难以写测试代码的可以跳过，通过实际运行验证

## 5.2 实现功能代码

以最小改动实现需求，不引入不必要的抽象或重构。

## 5.3 运行检查

每次改动后执行项目静态检查和测试。

## 5.4 提交

每个逻辑变更一个 commit，message 格式 `<type>(<scope>): <描述>`：
- **type** — `feat / fix / doc / refactor / perf / test / build / ci / chore`
- **scope** — 涉及的模块或功能区域；跨模块用 `*`
- **描述** — 简明扼要，中文优先

---

# Step 6: 验证与确认

变更完成后，逐项验证：

- [ ] 运行完整测试套件，全部通过
- [ ] 确认变更范围与 Step 4 计划一致，没有意外的文件被修改
- [ ] 没有 lint 错误或类型错误
- [ ] 若是 bug 修复类 issue，已复现问题并确认修复有效

> **必须等待用户确认后**才能进入 PR 阶段。用户提出修改意见的，回到 Step 5 重新实施后再验证。

---

> **用户确认后**：读取 `./DELIVER.md` 进入 PR 与合并阶段。
