# Step 3: 理解需求与范围

- 基于 Step 2 获取的 issue 内容，提取核心需求和验收条件
- 如果需求不明确，向用户提出澄清问题，不要猜测用户意图
- 确认影响范围和涉及的模块

## Step 4: 制定实现计划

使用 `EnterPlanMode` 进入计划模式，设计实现方案。计划必须包含：

1. **变更范围**——具体要改哪些文件，每个文件改什么
2. **实现步骤**——按什么顺序做，每步产出什么
3. **风险点**——可能出问题的地方，计划如何应对
4. **测试策略**——哪些需要单元测试，哪些通过实际运行验证

> **必须等待用户确认计划后才能继续。** 用户提出修改意见的，调整计划后重新确认。

---

> **用户确认后**：读取 `./IMPLEMENT.md` 进入实施阶段。
